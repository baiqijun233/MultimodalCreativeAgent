# AI 多模态创作与短剧生成 Agent 平台

## 项目定位

面向短剧和内容创作场景，将单点 Prompt 串联改造成可追踪、可恢复的多阶段 Agent 任务。用户输入创作意图后，平台依次完成需求解析、角色与场景规划、分镜生成、一致性校验、多模态资产任务编排和结果汇总。

## 本地已实现链路

1. `analyze`：校验输入并提取创作意图、内容类型和约束。
2. `plan`：输出角色、场景、分镜和图片/视频/音频素材类型。
3. `validate`：检查角色、场景、分镜数量和素材类型是否满足约束。
4. `assets`：为每种素材创建带任务编号的子任务，并归档到本地资产目录。
5. `finalize`：生成统一结果和资产数量，写入 SQLite 检查点。

每个阶段完成后立即保存状态；失败时保存当前阶段、重试次数、错误信息和事件。再次运行同一个任务 ID 时，会跳过已完成阶段，从失败阶段继续。

配置 `DEEPSEEK_API_KEY` 时，运行时默认优先使用 DeepSeek 完成需求解析和分镜规划；未配置密钥时回退到离线模型。DeepSeek 返回结果会校验必填字段、角色和场景结构、场景与分镜数量、分镜提示词以及素材类型，结构不合格时不会进入后续付费生成流程。

## 生产适配边界

当前仓库实际验证的是 Python 标准库状态机、SQLite、线程池异步执行、本地资产元数据归档和内存事件总线；Redis、Celery、WebSocket 已完成本地容器端到端验证。ArtClaw 已完成一次真实低成本视频生成、任务轮询和本地下载验收，结果保存在 `08_Deliverables`；这代表测试账号链路可用，不等同于生产环境上线承诺。可选图片服务已完成正式使用接入，并完成兼容接口的本机请求、图片落盘、分批幂等和失败续跑验证；当前电脑没有云飞密钥，无法在本轮重复复验。AWS S3 按约定跳过，资产默认保存本地。

当前代码已经达到“上线候选”状态：主业务、外部适配器、容器运行、健康检查、错误处理和验收记录均已完成。正式上线前只需将 Docker、持久化磁盘、Redis、域名/HTTPS 和密钥管理接入目标服务器，并按 [上线适配清单](上线适配清单.md) 做环境验证。

## 当前缺口

- 已提供轻量网页控制台，可创建和运行任务、查看任务列表、查看图片资产并执行清理预览。
- 已支持为每个分镜分别绑定公开 HTTPS 参考图、付费前预览和自动 `@图片N` 提示词；尚缺“本地参考图自动上传并换取远程可访问地址”的适配器。
- 图片生成已提供可选的兼容接口适配器和本地图片读取接口，不进入主状态机；音频和字幕仍以任务与元数据编排为主。
- 尚未实现多个分镜视频的自动剪辑、转场、配音、字幕和最终成片导出。
- 默认仅监听本机以降低误调用风险；若要多人或公网使用，还需要登录鉴权、权限、额度、审计和限流。
- 当前付费提交锁只覆盖单个 API 进程；多实例部署还需要 Redis 分布式锁、幂等键和生产监控。

## 未来升级计划

- 增加登录鉴权、角色权限、额度、审计和限流，支持多人或公网部署。
- 将单进程付费提交锁升级为 Redis 分布式锁和跨实例幂等键。
- 增加更细的任务归档策略、对象存储和生产监控告警。
- 增加多分镜自动剪辑、转场、配音、字幕和最终成片导出。

## 本次正式验收错误复盘

- DeepSeek 首次返回的 `scenes` 为结构化对象、`asset_types` 为单个字符串，导致原严格校验失败；现在只对这两种确定形态做规范化，其他缺字段和非法类型仍拒绝。
- ArtClaw 账户查询曾被 Cloudflare 以 HTTP 403 拦截；增加稳定应用 `User-Agent` 后恢复，账户查询、视频生成和下载均已成功。
- 视频下载曾返回容器内部 `/data/assets` 路径，宿主机无法直接访问；现在同时返回容器内部 `local_file` 和稳定 `download_url`。
- 容器重建后的首次健康探测曾遇到启动竞态 502；新增 `/ready` 和 Docker healthcheck，等待依赖就绪后再接收流量。
- 所有上述项目级错误均已有自动化测试或真实链路验证；当前没有未处理的已知阻塞错误。

## 面试讲解主线

重点解释三个设计决定：一是把剧本、角色、场景、分镜和资产任务拆开，便于单阶段重试；二是用结构化结果和一致性检查减少模型自由发挥；三是用检查点、事件和资产元数据让任务可查询、可恢复、可复盘。
