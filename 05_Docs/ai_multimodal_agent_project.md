# AI 多模态创作与短剧生成 Agent 平台

## 项目定位

面向短剧和内容创作场景，将单点 Prompt 串联改造成可追踪、可恢复的多阶段 Agent 任务。用户输入创作意图后，平台依次完成需求解析、角色与场景规划、分镜生成、一致性校验、多模态资产任务编排和结果汇总。

## 本地已实现链路

1. `analyze`：校验输入并提取创作意图、内容类型和约束。
2. `plan`：输出角色、场景、分镜和图片/视频/音频素材类型。
3. `validate`：检查角色、场景、分镜数量和素材类型是否满足约束。
4. `assets`：为每种素材创建带任务编号的子任务，并归档到本地资产目录。
5. `finalize`：生成统一结果和资产数量，写入 SQLite 检查点。

每个阶段完成后立即保存状态；失败时保存当前阶段、重试次数、错误信息和事件。再次运行同一个任务 ID 时，会跳过已完成阶段，从失败阶段继续。

配置 `DEEPSEEK_API_KEY` 时，运行时默认优先使用 DeepSeek 完成需求解析和分镜规划；未配置密钥时回退到离线模型。DeepSeek 返回结果会校验必填字段、角色和场景结构、场景与分镜数量、分镜提示词以及素材类型，结构不合格时不会进入后续付费生成流程。

## 生产适配边界

当前仓库实际验证的是 Python 标准库状态机、SQLite、线程池异步执行、本地资产元数据归档和内存事件总线；Redis、Celery、WebSocket 已完成本地容器端到端验证。ArtClaw 已完成一次真实低成本视频生成、任务轮询和本地下载验收，结果保存在 `08_Deliverables`；这代表测试账号链路可用，不等同于生产环境上线承诺。AWS S3 按约定跳过，资产默认保存本地。

## 当前缺口

- 暂无网页操作界面，当前通过 API、WebSocket 和启动脚本使用。
- 规划分镜可以批量提交 ArtClaw，但尚未实现“每个分镜分别绑定角色、服装和场景参考图”的本地资产映射。
- 图片和音频资产阶段目前以任务和元数据编排为主，尚未接入真实生图、配音和字幕服务。
- 尚未实现多个分镜视频的自动剪辑、转场、配音、字幕和最终成片导出。
- 默认仅监听本机以降低误调用风险；若要多人或公网使用，还需要登录鉴权、权限、额度、审计和限流。
- 当前付费提交锁只覆盖单个 API 进程；多实例部署还需要 Redis 分布式锁、幂等键和生产监控。

## 面试讲解主线

重点解释三个设计决定：一是把剧本、角色、场景、分镜和资产任务拆开，便于单阶段重试；二是用结构化结果和一致性检查减少模型自由发挥；三是用检查点、事件和资产元数据让任务可查询、可恢复、可复盘。
